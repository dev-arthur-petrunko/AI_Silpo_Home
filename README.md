# 🤖 AI Silpo Home — спільні закупівлі «Сільпо» у Telegram

Telegram-бот, який організовує спільні закупівлі продуктів для мешканців будинку
за оптовою акцією **«Гуртом дешевше»** (промо `melkoopt` у Сільпо). Бот сканує
акції, постить вигідні товари в групу, збирає кількість від сусідів через кнопки
і передає зведене замовлення будинку менеджеру — зі статусами і підтвердженням.

---

## ✨ Що вміє

### 🛒 Життя угоди
- **Скан акцій** — автоматичний за розкладом: **10:00, 14:00, 16:00** (Europe/Kyiv),
  або вручну командою `/scan` у групі. Постить товари зі знижкою **≥25%**, з фото,
  ціною за одиницю, розміром партії, економією і дедлайном збору.
- **Анти-дублікати** — для кожної групи окремо пам'ятає, які товари постили за
  останній тиждень, і не дублює їх (навіть якщо стара угода закрилась).
- **Місто групи** — адмін один раз обирає місто в меню (`/settings`, 17 міст).
  Ціни, склад, розмір партій і наявність рахуються **для міста саме цієї групи**;
  скан на плановий час іде по кожному унікальному місту окремо.
- **Наявність у магазині** — кнопка `🔎 Наявність` на пості показує актуальний
  залишок товару (`stock`) у магазині міста групи на момент натискання.
- **Різноманітність** — жодна категорія не займає більше половини батчу
  (з 10 постів не буде 10 прокладок), а вільні місця дозаповнюються категоріями,
  які ця група раніше ігнорувала.
- **Кнопки кількості** — `➕ / ➖` додають/зменшують чернетку, `✅ Підтвердити`
  додає її до замовлення. Пост завжди показує «Зібрано N/партія» та список
  тих, хто очікує підтвердження.
- **Ізоляція груп** — кожна група жильців незалежна: `/scan` публікує тільки в ту
  групу, звідки викликаний, угоди й замовлення в групі не змішуються.
- **Клікабельні посилання** — назва товару веде на сторінку silpo.ua без голих URL
  і без небажаних прев'ю в повідомленнях.

### 🏠 Замовлення будинку
- `/order` — весь заказ учасника, або зведення по будинку.
- **Оформлення для менеджера** — адмін натискає «📦 Оформити замовлення», пише
  дані доставки вільним текстом (бот сам розбере місто/адресу/час/телефон):
  `Київ | вул. Хрещатик, 1, кв. 5 | 18:00-21:00 | +380 50 123 45 67`.
- Після передачі менеджеру список замовлень **автоматично скидається** — новий збір
  можна починати одразу (пости повертаються до збору, публікації не видаляються).

### 📊 Статуси замовлення
- Окремий **бот менеджера** отримує зведення замовлення з кнопками статусу:
  ✅ Підтверджено · ❌ Скасовано · 📦 Комплектується · 🚚 В дорозі · 🎉 Виконано.
- Зміна статусу оновлює повідомлення менеджера і **сповіщає саме ту групу**,
  звідки прийшло замовлення.
- Жильці бачать статус будинку командою `/status` або кнопкою «📊 Статус замовлення».

### 🎯 Персоналізація
- **Релевантність під будинок** — TF-IDF + cosine-схожість обирають товари, які ця
  група реально замовляє (з урахуванням того, що ігнорували).
- **Тон переписки** — бот аналізує стиль спілкування групи через LLM (Groq) і пише
  вступи/заклики до постів у стилі саме цієї групи.
- **Предиктивні нагадування** — сусіду, який регулярно бере певну категорію, бот
  пише в приват, коли збирається нова партія.
- 🔎 **Конфіденційність:** зберігаються лише останні ~100 повідомлень групи,
  старі автоматично видаляються.

## 📚 Команди

| Команда       | Що робить                                                        |
|---------------|------------------------------------------------------------------|
| `/order`      | Переглянути свій заказ (або зведення по будинку)                 |
| `/status`     | Статус замовлення будинку                                        |
| `/scan`       | Запустити скан угод у цій групі                                  |
| `/reset`      | Скинути список замовлення (адміністратор / власник)              |
| `/settings`   | Встановити місто групи (меню-вибір, один раз)                    |
| `/debug`      | Стан бота, налаштування сканера                                  |
| `/register`   | Зареєструвати групу (автоматично при додаванні бота)             |

Два боти: **основний** (для жильців, повне меню) і **менеджерський** (приймає
замовлення, `/status` по всіх групах).

## 🧠 Як тут використовується AI

Єдиний LLM-клієнт — `core/llm.py` (Groq, `llama-3.3-70b-versatile`,
OpenAI-сумісний API через httpx): `llm_text` (текст) і `llm_json`
(структурований JSON). Він використовується у двох місцях:

**1. Аналіз тону групи** — `core/tone_profiler.py`

Кожне повідомлення групи зберігається в таблицю `messages` (тільки останні
~100, старі видаляються). Коли набралось ≥`tone_min_messages` повідомлень,
LLM аналізує останні 60 і повертає профіль, який кешується в `groups.tone_profile`:

```json
{
  "tone": "дружній",
  "formality": "неформальний",
  "emoji": true,
  "exclamations": true,
  "post_intro": "Сусіди, дивіться що знайшла! 🔥",
  "post_outro": "Хто бере — тисни ➕, зберу за всіх!"
}
```

`post_intro` / `post_outro` підставляються в пости угод цієї групи
(`bot/texts.py`), тож кожен будинок отримує повідомлення «у своєму стилі».
Профіль рахується одноразово, перерахунок — лише для груп без профілю.

**2. Предиктивні нагадування** — `core/reminders.py`

Коли публікується нова угода, бот шукає сусідів, які регулярно брали цю
категорію (частота рахується з історії приєднань), і LLM пише їм короткий
приватний текст: «ти зазвичай береш це раз на місяць, зараз збирається
партія — приєднатись?».

**MCP як AI-шар:**

- `core/mcp_client.py` — клієнт **MCP (Model Context Protocol)** — AI-орієнтованого
  протоколу підключення моделей до даних та інструментів. Ми використовуємо
  MCP-сервер Сільпо (`https://mcp.silpo.ua/mcp`) як **джерело даних**: товари,
  ціни, залишки (`stock`), контекст доставки за містом. Це та сама інфраструктура,
  через яку LLM-агент отримував би контекст, але в боті запити робить наш код
  (JSON-RPC over HTTP, без виклику LLM).

**Що AI не є:**

- `core/relevance_scorer.py` — **TF-IDF + cosine-схожість**: класична математика,
  без LLM і без мережі.

**Fallback:** якщо `GROQ_API_KEY` не задано — `LLMError` ловиться, і бот працює
по нейтральних шаблонах: пости без тонованого вступу, нагадування за шаблоном.

## 🧱 Стек

- **Python 3.14**, **aiogram 3** (async), **APScheduler**, **SQLAlchemy 2** (async) + **Alembic**
- **БД:** PostgreSQL у продакшні, SQLite — локально (`DATABASE_URL`)
- **MCP-клієнт:** MCP (Model Context Protocol) Сільпо — `https://mcp.silpo.ua/mcp` (streamable HTTP, JSON-RPC, Bearer-токен, tenacity-retry)
- **LLM:** Groq (tone-profiler, нагадування) через звичайний httpx
- Тести: `pytest` (63 passed)

## 🚀 Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env        # вписати токени ботів і MCP_API_KEY
alembic upgrade head          # застосувати міграції
python main.py                # запуск основного + менеджерського бота
```

Локальна розробка на SQLite: `DATABASE_URL=sqlite+aiosqlite:///./dev.db`

## 🗂️ Структура

```
main.py                 Точка входу: полінг обох ботів, хендлери, меню
bot/
  commands.py           Меню команд (Telegram Menu), текст привітання
  keyboards.py          Кнопки: угоди, замовлення, статуси менеджера
  texts.py              Форматування постів, замовлень, статусів
core/
  mcp_client.py         Клієнт MCP «Сільпо» (товари, доставка, ціни)
  promo_scanner.py      Скан акцій, публікація в групи, розклад (APScheduler)
  orders.py             Чернетки, підтвердження, зведення, передача менеджеру
  relevance_scorer.py   Ранжування товарів під профіль будинку (TF-IDF)
  tone_profiler.py      Аналіз тону групи через LLM
  reminders.py          Предиктивні нагадування сусідам
  savings.py            Розрахунок економії та знижок
  llm.py                Мінімальний LLM-клієнт (Groq, OpenAI-сумісний)
  config.py             Налаштування (pydantic-settings)
db/
  models.py             Group, Deal, Participant, TelegramUser, GroupMessage
  migrations/           Alembic-міграції
scripts/                Dev-утиліти: probe_mcp, run_scan, preview_ui, smoke_test
tests/                  pytest-набір (сканер, замовлення, статуси, тонування...)
```
